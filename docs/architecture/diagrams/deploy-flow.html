Fluxo de deploy

Todo push e todo PR rodam o CI. Quando o CI de um push na main termina verde, o workflow de deploy aplica as migrations no Neon pela conexão direta, chama o Deploy Hook do Render e espera /health responder 200. O app em produção usa a conexão pooled do Neon.

Arraste o diagrama para o lado para ver tudo.

Fonte: .github/workflows/ci.yml, .github/workflows/deploy.yml, render.yaml, Dockerfile e docs/devops/DEPLOY.md. Segredos do deploy ficam no environment production do GitHub (APP_URL pode ser variável ou segredo); os do app ficam nas variáveis de ambiente do serviço no Render (VITE_DEMO_* também, repassadas ao build). O TEST_DB_CONNECTION do CI aponta para um Postgres descartável e não é segredo. O Render constrói a imagem a partir do Dockerfile; o job docker do CI só confere que o build passa.
